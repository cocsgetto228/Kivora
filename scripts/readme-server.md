# Kivora — поставка для сервера

Мессенджер со сквозным шифрованием. Один статический бинарник, внутри которого
уже лежит веб-клиент: ни Node, ни базы данных, ни отдельного веб-сервера для
статики не нужно.

## Что в коробке

```
bin/kivorad-linux-amd64     сервер для обычного x86-64
bin/kivorad-linux-arm64     сервер для ARM (Raspberry Pi, Ampere, Graviton)
install.sh                  установка службы systemd
deploy/                     Caddy, nginx, Docker, юнит systemd, страница 404
DEPLOY.md                   все настройки, обновление, резервные копии
CORE-PROTECTION.md          модель угроз и что нужно сделать вам, а не серверу
```

## Установка за одну команду

```sh
sudo ./install.sh
```

Скрипт заводит системного пользователя `kivora`, кладёт бинарник в
`/usr/local/bin`, создаёт `/var/lib/kivora` с правами 0700 и запускает службу.
Повторный запуск обновляет установку, данные не трогает.

Дальше поставьте перед ним TLS-терминатор — конфиги Caddy и nginx в `deploy/`.
Сервер намеренно не занимается сертификатами.

## Без systemd

```sh
KIVORA_DATA_DIR=/var/lib/kivora ./bin/kivorad-linux-amd64
```

Слушает `:8080`. Всё остальное настраивается переменными окружения, см.
`DEPLOY.md`.

## Docker

```sh
docker compose -f deploy/docker-compose.yml up -d
```

Образ собирается на базе `scratch`: внутри только бинарник и корневые
сертификаты.

## Первое, что надо сделать после установки

1. **Зарегистрируйтесь.** Первый созданный аккаунт становится администратором
   сервера. Сделайте это раньше, чем адрес станет публичным.
2. **Закройте регистрацию**, если сервер приватный:
   `KIVORA_REGISTRATION=invite` и `KIVORA_INVITE_CODES=...`.
3. **Проверьте страницы ошибок** — админ-консоль, раздел «Страницы». Там же
   есть проверка кода ответа: страница 404, отданная с кодом 200, выглядит
   правильно для человека и неправильно для любого монитора.
4. **Настройте резервное копирование** `/var/lib/kivora`. Файл `secret.key`
   обязателен: без него все сессии станут недействительными.

## Админ-консоль

Живёт по адресу `/admin` — отдельная страница, не вкладка внутри мессенджера.
Показывает счётчики, активность за неделю, пользователей, каналы и политику
установки.

Содержимого сообщений там нет и быть не может: на сервере они зашифрованы, и
админским обработчикам просто нечего показать. Это свойство архитектуры, а не
настройка, которую можно случайно выключить.

## Звонки

Работают через WebRTC напрямую между участниками — медиа через сервер не идёт.
Чтобы они соединялись через NAT, нужен TURN:

```
KIVORA_TURN_URL=turn:turn.example.org:3478
KIVORA_TURN_USER=... KIVORA_TURN_PASS=...
```

Без TURN клиент честно покажет, что связь может не установиться. Для закрытого
контура уберите публичный STUN из `KIVORA_STUN_URLS`, иначе адреса ваших
пользователей уходят наружу.
