# HTTP и WebSocket API

Базовый путь — `/api/v1`. Аутентификация — заголовок `Authorization: Bearer <токен>`.
Все двоичные поля — base64 (стандартный алфавит).

Главное свойство: **тело сообщения, его заголовок и завёрнутые ключи непрозрачны
для сервера.** Ни один обработчик их не разбирает.

## Публичные

### `GET /server`

Что это за сервер и что он принимает. Клиент вызывает это до входа, чтобы выбрать
набор шифров.

```json
{
  "name": "Kivora", "version": "0.1.0", "protocol": 1,
  "registrationMode": "open", "requireE2E": false,
  "allowedSuites": ["*"],
  "suites": [{ "id": "kivora.x25519-xchacha20poly1305.v1", "recommended": true }],
  "maxMessageBytes": 131072,
  "maxUploadBytes": 67108864,
  "maxFileBytes": 33554432,
  "maxAvatarBytes": 2097152,
  "calls": true
}
```

`calls` говорит, настроен ли на сервере хотя бы один STUN или TURN: без них
клиент прячет кнопку звонка, а не показывает ту, которая не сработает.

### `POST /auth/register`

```json
{ "username": "ivan", "displayName": "Иван", "password": "…", "inviteCode": "…" }
```

Первый зарегистрированный аккаунт получает права администратора. Ответ — токен и
пользователь. Устройство регистрируется отдельным вызовом сразу после.

### `POST /auth/login`

`{ "username": "...", "password": "..." }` → токен и пользователь.

Ответ на несуществующий логин занимает столько же времени, сколько на неверный
пароль.

## Аккаунт

| Метод и путь        | Что делает                                     |
| ------------------- | ---------------------------------------------- |
| `POST /auth/logout` | Гасит текущий токен                            |
| `GET /me`           | Профиль и идентификатор устройства этой сессии |
| `PATCH /me`         | `{ displayName, bio }`                         |
| `GET /users?q=`     | Поиск пользователей (минимум два символа)      |

## Файлы и аватары

Загрузка идёт **сырыми байтами** в теле запроса, метаданные — в query. Причина
простая: 20-мегабайтное видео в base64 внутри JSON весит 27 МБ на проводе и
требует второй копии в памяти при разборе; multipart добавляет разбор без выгоды.

### `POST /uploads?channel=<id>&mime=<тип>&w=&h=&d=`

Тело — байты. Для сквозного чата это **уже шифротекст**: ключ файла лежит внутри
зашифрованного сообщения, а не рядом с файлом. Сервер проверяет членство,
проверяет тип (`text/html`, `application/javascript`, `image/svg+xml` и
`application/xhtml+xml` отклоняются), пишет байты и возвращает метаданные —
`{ "upload": { id, mime, size, width, height, duration } }`.

`w`, `h`, `d` — ширина, высота и длительность для превью: они нужны, чтобы
разметка не прыгала до расшифровки. Всё остальное о файле сервер не знает.

### `GET /uploads/{id}`

Отдаёт байты участнику канала. Ответ помечен `Content-Type:
application/octet-stream`, `Content-Disposition: attachment` и `nosniff`:
шифротекст браузер выполнить не должен ни при каких обстоятельствах.
Шифротекст по идентификатору не меняется, поэтому кешируется навсегда.

### `POST /uploads/avatar?mime=<тип>` и `GET /avatars/{id}`

Аватар хранится **открытым** — это единственный пользовательский контент,
который сервер видит. Причина и цена описаны в [CRYPTO.md](CRYPTO.md#аватары).
Разрешены png/jpeg/webp/gif, тип сверяется с сигнатурой файла, а не со словами
клиента; клиент дополнительно пережимает картинку в WebP 256×256, что заодно
срезает EXIF (включая координаты).

## Устройства и ключи

### `POST /devices`

Публикует **открытые** половины ключей и привязывает сессию к новому устройству.

```json
{
  "name": "Ноутбук", "platform": "linux",
  "suite": "kivora.x25519-xchacha20poly1305.v1",
  "identityPub": "<ed25519 ‖ x25519, base64>",
  "signedPreKeyPub": "<base64>",
  "signedPreKeySig": "<base64>",
  "preKeys": [{ "id": "abc", "pub": "<base64>" }]
}
```

Идентификаторы предключей выбирает клиент: только он знает, какому закрытому
ключу они соответствуют, а закрытые ключи он не отправляет.

| Метод и путь                | Что делает                                                     |
| --------------------------- | -------------------------------------------------------------- |
| `POST /devices/{id}/attach` | Привязать сессию к уже существующему своему устройству          |
| `GET /devices`              | Свои устройства                                                 |
| `DELETE /devices/{id}`      | Отозвать: устройство теряет сессии и перестаёт получать ключи    |
| `POST /devices/prekeys`     | Пополнить запас одноразовых предключей                          |
| `GET /keys/{userId}`        | Связки ключей: по одной на устройство, с тратой предключа        |
| `POST /keys/backfill`       | Передать переупакованные ключи **своему** другому устройству     |

## Каналы

| Метод и путь                    | Что делает                                              |
| ------------------------------- | ------------------------------------------------------- |
| `GET /channels`                 | Боковая панель: чаты, непрочитанные, участники, кто в сети |
| `POST /channels`                | Создать группу или открытый канал                       |
| `GET /channels/browse`          | Открытые каналы, куда можно войти                       |
| `POST /channels/direct`         | Открыть личный чат (идемпотентно)                       |
| `GET /channels/{id}`            | Один канал                                              |
| `PATCH /channels/{id}`          | Название и тема (только владелец)                       |
| `POST /channels/{id}/join`      | Войти в открытый канал                                  |
| `POST /channels/{id}/leave`     | Выйти                                                   |
| `POST /channels/{id}/members`   | Добавить участника                                      |
| `GET /channels/{id}/devices`    | **Для кого заворачивать ключи.** Только участникам       |
| `PATCH /channels/{id}/membership`| Свои флажки чата: `{ archived, pinned, muted }`         |
| `POST /channels/{id}/clear`     | Сжечь **свои** сообщения в чате                         |
| `GET /channels/{id}/threads`    | Ветки этой группы, где вы участник                      |
| `POST /channels/{id}/threads`   | Создать ветку: `{ name, members, suite? }`              |

Флажки членства — личные: «архив» и «закрепить» у вас не меняют чат ни для кого
другого. Архивные чаты уходят из основного списка, закреплённые всплывают наверх.

Ветка — это канал с `parentId` и **своим составом участников**. Ключи в ней
заворачиваются только для устройств её участников, так что остальная группа
видит факт существования ветки, но не её содержимое. Набор шифров ветки можно
задать свой; по умолчанию наследуется родительский.


## Сообщения

### `POST /channels/{id}/messages`

```json
{
  "kind": "text",
  "suite": "kivora.x25519-xchacha20poly1305.v1",
  "header": "<base64, непрозрачно>",
  "body":   "<base64, шифротекст>",
  "keys":   { "<deviceId>": "<base64, завёрнутый ключ>" },
  "replyTo": "", "clientId": "для дедупликации"
}
```

Сервер проверяет членство, сверяет набор шифров с каналом и **отбрасывает ключи
для устройств, не входящих в чат**.

### `GET /channels/{id}/messages?before=<seq>&limit=<n>`

Возвращает историю от старых к новым. У каждого сообщения — `wrappedKey`,
завёрнутый **только для запрашивающего устройства**.

| Метод и путь                  | Что делает                                    |
| ----------------------------- | --------------------------------------------- |
| `POST /channels/{id}/read`    | Отметка прочтения `{ seq }`                   |
| `DELETE /messages/{id}`       | Удалить у всех: ключи стираются, тело — тоже  |
| `POST /channels/{id}/typing`  | Сигнал «печатает»                             |
| `POST /messages/{id}/pin`     | Закрепить сообщение                           |
| `DELETE /messages/{id}/pin`   | Открепить                                     |
| `GET /channels/{id}/pinned`   | Закреплённые сообщения канала                 |

## Звонки

Сигнализация идёт по WebSocket, медиа — напрямую между браузерами (WebRTC,
полносвязная сеть). Сервер не проксирует ни звук, ни видео и не может их
записать; он передаёт SDP и ICE-кандидатов между участниками одного канала.

### `GET /ice`

```json
{ "iceServers": [{ "urls": ["stun:stun.l.google.com:19302"] }], "hasRelay": false }
```

Список STUN/TURN из настроек сервера. `hasRelay` говорит клиенту, честно ли
обещать связь через NAT: без TURN два участника за симметричным NAT не соединятся.

**Честно про шифрование:** медиапоток защищён DTLS-SRTP, то есть шифруется между
браузерами, но отпечатки DTLS приходят через сервер. Сервер, который решит
подменить их, встанет в середину. Это ровно тот случай, о котором говорил
заказчик — «первоначально в открытом виде»: сквозной защиты уровня переписки
здесь пока нет, и документация это не скрывает.

**Заголовок `Permissions-Policy`** отдаётся как
`camera=(self), microphone=(self), display-capture=(self)`, всё остальное
запрещено. Полный запрет камеры и микрофона выглядит осторожнее, но ломает
звонки молча: `getUserMedia` отклоняется по нарушению политики ещё до того, как
у человека что-то спросят.

## Администрирование

Только для аккаунтов с `isAdmin`. Важное свойство: **ни один админский
обработчик не отдаёт содержимое сообщений** — их просто нет в открытом виде.

| Метод и путь                     | Что отдаёт                                                  |
| -------------------------------- | ----------------------------------------------------------- |
| `GET /admin/overview`            | Счётчики, ряды за 7 дней, политика установки, состояние Go   |
| `GET /admin/users`               | Пользователи: устройства, онлайн, флаги                      |
| `POST /admin/users/{id}/flags`   | `{ isAdmin, suspended }` — блокировка гасит сессии           |
| `GET /admin/channels`            | Чаты: тип, число участников и сообщений — **без текста**     |
| `POST /admin/compact`            | Уплотнить журнал                                             |

`GET /admin/overview` возвращает `users/online/channels/messages/devices`,
`fileBytes`, `logBytes`, `uptimeSec`, ряды `messagesPerDay` и `signupsPerDay`
с подписями `days`, восемь последних регистраций, блок `policy` (режим
регистрации, разрешённые наборы шифров, лимиты, режим fsync) и блок `runtime`
(версия Go, ОС, архитектура, число горутин, куча в МБ).

Последний администратор не может снять с себя права и не может себя
заблокировать: иначе установка осталась бы без управления.

## WebSocket

`GET /api/v1/ws?token=<токен>` — токен в параметре, потому что браузер не умеет
задавать заголовки при рукопожатии WebSocket; проверяется он так же, как bearer,
и не логируется.

События приходят как `{"type": "...", "channel": "...", "data": {...}, "ts": 0}`:

| Тип               | Когда                                                            |
| ----------------- | ---------------------------------------------------------------- |
| `ready`           | Соединение установлено                                           |
| `message.new`     | Новое сообщение — с ключом **для этого устройства**               |
| `message.deleted` | Сообщение удалено                                                |
| `channel.created` | Вас добавили в чат или вы его создали                            |
| `channel.updated` | Изменились название или тема                                     |
| `channel.members` | Изменился состав                                                 |
| `channel.bump`    | В канале активность — обновите список                            |
| `presence`        | Кто-то из ваших собеседников появился или ушёл                   |
| `typing`          | Собеседник печатает                                              |
| `message.pinned`  | Сообщение закрепили или открепили                                |
| `channel.cleared` | Кто-то сжёг свои сообщения — перезагрузите историю               |
| `thread.created`  | Вас добавили в ветку                                             |
| `call.ring`       | Вас зовут в звонок                                               |
| `call.state`      | Изменился состав звонка или флажки участников (микрофон, камера) |
| `call.signal`     | SDP или ICE-кандидат — адресно, одному устройству                |
| `call.decline`    | Собеседник отклонил вызов — звонящий перестаёт звонить            |
| `session.revoked` | Устройство отозвано или аккаунт заблокирован                     |

Клиент может слать `ping`, `typing`, а также сообщения звонка: `call.ring`,
`call.join`, `call.flags` (микрофон/камера/экран), `call.decline`, `call.leave`
и `call.signal` (адресуется конкретному устройству —
`{"to":"<userId>","toDevice":"<deviceId>"}`). Каждое из них проверяет членство
в канале: сигнализация — не способ дотянуться до произвольных устройств.

**Отказ и тишина.** `call.decline` существует потому, что «нет» — это ответ, и
он должен доходить. Если же никто не отвечает вовсе, звонящий сам прекращает
дозвон через 45 секунд, а у вызываемого баннер гаснет через минуту: звонок,
который звонит вечно, — не нейтральное поведение, а способ оставить обоих в
неведении.
Всё, что меняет состояние, идёт через REST, где действует одна и та же проверка
для всех клиентов.

## Ошибки

`{"error": "код"}` с осмысленным HTTP-статусом:

| Код                  | Статус | Смысл                                    |
| -------------------- | ------ | ---------------------------------------- |
| `missing_token`      | 401    | Нет заголовка `Authorization`            |
| `invalid_token`      | 401    | Токен просрочен или отозван              |
| `invalid_credentials`| 401    | Неверный логин или пароль                |
| `not_a_member`       | 403    | Не участник чата                         |
| `registration_closed`| 403    | Регистрация закрыта                      |
| `too_many_devices`   | 403    | Достигнут лимит устройств                |
| `username_taken`     | 409    | Логин занят                              |
| `message_too_large`  | 413    | Больше `maxMessageBytes`                 |
| `rate_limited`       | 429    | Слишком часто; см. `Retry-After`         |
| `suite_rejected`     | 400    | Набор шифров не разрешён или неформатен  |
| `unsupported_media`  | 400    | Тип файла запрещён или не совпал с сигнатурой |
| `upload_too_large`   | 413    | Больше `KIVORA_MAX_FILE_MB` / `KIVORA_MAX_AVATAR_KB` |
| `threads_need_a_group`| 400   | Ветку можно создать только в группе или канале |
| `not_found`          | 404    | Нет такого объекта или он вам не виден   |
