# Архитектура

## Одной картинкой

```
     ┌─────────────────────┐        ┌─────────────────────┐
     │  Desktop (Tauri)    │        │  Браузер            │
     │  ┌───────────────┐  │        │  ┌───────────────┐  │
     │  │ WebView       │  │        │  │ React + Vite  │  │
     │  │ React + Vite  │  │        │  └───────┬───────┘  │
     │  └───────┬───────┘  │        │          │          │
     │   IPC    │          │        │          │          │
     │  ┌───────┴───────┐  │        │          │          │
     │  │ Rust-ядро:    │  │        │          │          │
     │  │ ключ в ОС,    │  │        │          │          │
     │  │ троттлинг     │  │        │          │          │
     │  └───────────────┘  │        │          │          │
     └──────────┬──────────┘        └──────────┬──────────┘
                │      HTTPS + WebSocket       │
                └───────────────┬──────────────┘
                                │
                   ┌────────────┴─────────────┐
                   │      kivorad (Go)         │
                   │  ┌────────────────────┐  │
                   │  │ guard: CSP, лимиты │  │
                   │  ├────────────────────┤  │
                   │  │ api: REST + WS     │  │
                   │  ├────────────────────┤  │
                   │  │ hub: рассылка      │  │
                   │  ├────────────────────┤  │
                   │  │ store: журнал      │  │
                   │  └────────────────────┘  │
                   │  meta.log + blobs.dat    │
                   └──────────────────────────┘
```

Ключевая линия проходит по стрелке «HTTPS»: **всё, что её пересекает в сторону
сервера, уже непрозрачно**. Сервер — это надёжный почтовый ящик с правами
доступа, а не участник разговора.

## Сервер

Go, только стандартная библиотека. Пакеты:

| Пакет                    | Ответственность                                                     |
| ------------------------ | ------------------------------------------------------------------- |
| `internal/config`        | Конфигурация из переменных окружения, у всего есть рабочее значение   |
| `internal/guard`         | Ограничение частоты, заголовки безопасности, CORS, размер тела, паники|
| `internal/api`           | HTTP-обработчики. Роутер — `net/http` (Go 1.22 умеет метод+путь)     |
| `internal/hub`           | Реестр живых соединений, рассылка событий, комнаты звонков           |
| `internal/store`         | Единственное место, где происходит запись на диск                    |
| `internal/ws`            | WebSocket по RFC 6455                                               |
| `internal/crypto/*`      | Argon2id, BLAKE2b                                                   |
| `internal/suite`         | Политика: какие наборы шифров разрешены на этой установке            |
| `internal/webui`         | Встроенный веб-клиент (`go:embed`), 404 для неизвестных путей        |

### Почему ноль зависимостей

Сервер мессенджера — привлекательная цель для атаки на цепочку поставок. Каждая
строка в `go.mod` — это код с доступом к метаданным ваших пользователей,
обновляемый кем-то другим. Поэтому три вещи, которые обычно берут из библиотек,
написаны здесь:

* **Argon2id** (`internal/crypto/argon2`) — от него зависит, сколько стоит
  перебор украденной базы. Сверен с тест-вектором RFC 9106 §5.3.
* **WebSocket** (`internal/ws`) — нужное подмножество RFC 6455 читается за один
  присест; permessage-deflate намеренно не реализован (сжатие рядом с секретами —
  это CRIME и BREACH, а шифротекст всё равно не сжимается).
* **Хранилище** (`internal/store`) — см. ниже.

Побочные выгоды: сборка работает без сети, кросс-компиляция не требует C-тулчейна,
а `go.sum` пустой.

### Хранилище

Два файла в каталоге данных:

```
meta.log    журнал только на дозапись: каждая запись — одно изменение состояния
blobs.dat   непрозрачные байты: шифротексты, карты завёрнутых ключей, файлы
```

Файлы живут в том же `blobs.dat`, что и тела сообщений, и по той же причине: для
сервера это просто отрезок байт со смещением и длиной. Отдельного каталога с
вложениями нет — значит, нет и отдельного способа его случайно раздать.

При старте журнал проигрывается в память. Дальше чтения обслуживаются из памяти
(блобы читаются с диска по требованию), запись — это одна дозапись плюс, по
настройке, `fsync`.

Компромисс осознанный:

* убирает последнюю стороннюю зависимость,
* память тратится пропорционально **метаданным**, а не объёму сообщений,
* сервер запускается везде, где есть каталог с правом записи,
* но произвольных SQL-запросов нет — мессенджеру они и не нужны.

Каждая запись защищена CRC32. Обрыв на середине оставляет короткий или битый
хвост; проигрывание останавливается на первой плохой записи и обрезает файл, так
что недописанное сообщение — это просто сообщение, которое не дошло. Тест
`TestTornTailIsTruncated` дописывает мусор в журнал и проверяет, что сервер
поднимается, отдаёт целые данные и продолжает писать.

Уплотнение (`Compact`) переписывает оба файла из живого состояния через временные
файлы и `rename`, поэтому падение во время уплотнения оставляет прежнюю рабочую
базу.

Если понадобится PostgreSQL — реляционная форма тех же данных лежит в
[reference/schema.sql](reference/schema.sql), а набор методов `store.Store`
и есть весь интерфейс, который надо реализовать.

## Модель данных

* **user** — аккаунт: логин, отображаемое имя, хеш пароля Argon2id.
* **device** — одна установка. У неё своя долговременная пара ключей. Отзыв
  потерянного ноутбука не требует смены ключей на остальных устройствах.
* **channel** — `dm` (личный), `group` (закрытая группа) или `channel`
  (открытый канал в духе Mattermost). Первые два всегда сквозные. У канала может
  быть `parentId` — тогда это **ветка**: отдельный список участников, отдельные
  завёрнутые ключи, при желании отдельный набор шифров.
* **upload** — файл или аватар: владелец, канал, MIME, размеры, смещение в
  `blobs.dat`. Для файла в сквозном чате байты — шифротекст; для аватара — нет.
* **membership flags** — «архив», «закрепить», «без звука». Хранятся на паре
  (канал, пользователь): это личный взгляд на чат, а не свойство чата.
* **message** — непрозрачное тело, непрозрачный заголовок, порядковый номер.
* **message_keys** — ключ содержимого, завёрнутый **для каждого устройства**.
  Удаление сообщения стирает эти ключи, поэтому «удалить у всех» работает даже
  против того, у кого есть старая копия файла блобов.

## Звонки

`internal/hub/calls.go` держит комнаты: кто сейчас в звонке в каком канале и с
какими флажками (микрофон, камера, экран). Это единственное состояние звонка на
сервере — ни звук, ни видео через него не идут.

Медиа устанавливается напрямую между браузерами: полносвязная сеть
`RTCPeerConnection` с «вежливым/невежливым» разрешением коллизий (роль
выбирается сравнением идентификаторов устройств, поэтому не нужен арбитр).
Сервер только пересылает SDP и ICE-кандидатов адресно нужному устройству и
раздаёт список STUN/TURN из настроек.

Честная граница: DTLS-SRTP шифрует поток между браузерами, но отпечатки
проходят через сервер, поэтому недоверенный сервер теоретически может встать в
середину звонка. Для переписки это не так — там ключи проверяются вручную
(см. [CRYPTO.md](CRYPTO.md)). Звонки в этой версии сознательно слабее, и это
записано, а не умолчано.

## Реальное время

`internal/hub` держит соединения, сгруппированные по пользователю. Рассылка
сообщения — это `ToUserDevices`: каждому устройству уходит **его** завёрнутый
ключ и ничьи чужие. Медленный потребитель отключается, а не тормозит отправителя:
реальное время — это ускорение, источник истины — история по REST.

## Клиент

Веб-клиент — React + Vite, без библиотек состояния и без UI-фреймворка.
Состояние живёт в классе `Session` и раздаётся через `useSyncExternalStore` —
пятнадцать строк вместо зависимости. Рядом с ним три вспомогательных модуля:
`lib/calls.ts` (WebRTC), `i18n/` (словари и автоопределение языка по
`navigator.languages`) и `data/emoji.ts` (набор эмодзи с поиском по русским и
английским словам — данные, а не библиотека).

`Session` — единственное место в клиенте, которое видит открытый текст и закрытые
ключи. Компоненты читают снимок состояния и вызывают действия. Граница проведена
специально: чтобы проверить заявления о безопасности, достаточно прочитать один
файл.

## Десктоп

Оболочка Tauri намеренно тонкая: тот же веб-клиент плюс три вещи, которых браузер
дать не может, — секрет устройства в хранилище ОС, троттлинг подбора пароля,
который нельзя сбросить очисткой сайта, и окно с перечисленными разрешениями.
Криптографии в Rust нет: вывод ключей и шифрование остаются в одном проверенном
месте, а не разъезжаются по двум языкам.

## Поток сообщения целиком

1. Пользователь нажимает Enter.
2. `Session.sendMessage` берёт список устройств чата (`GET /channels/{id}/devices`)
   и, для новых устройств, одноразовые предключи (`GET /keys/{userId}`).
3. `seal()` создаёт ключ содержимого, шифрует тело один раз и заворачивает ключ
   для каждого устройства.
4. `POST /channels/{id}/messages` отправляет заголовок, тело и карту завёрнутых
   ключей — всё в base64, всё непрозрачно.
5. Сервер проверяет членство, **выбрасывает ключи для устройств не из чата**,
   присваивает номер и сохраняет.
6. `hub` рассылает событие каждому живому устройству — со своим ключом.
7. У получателя `openSealed` разворачивает ключ, проверяет отправителя и
   расшифровывает.

Если к сообщению приложены файлы, шаг 3 идёт немного иначе: для каждого файла
создаётся **одноразовый ключ файла**, файл шифруется им и уходит в `POST
/uploads`, а сам ключ кладётся **внутрь** полезной нагрузки сообщения — той
самой, что шифруется на шаге 3. Поэтому доступ к файлу — это следствие доступа к
сообщению, и отдельного разрешения на файлы не существует.

Шаг 5 — не формальность: без него отправитель мог бы «случайно» завернуть ключ
для устройства постороннего. Тест `TestKeysForNonMemberDevicesAreDropped`
проверяет именно это.
