# Развёртывание

Сервер — один файл без зависимостей. Всё, что ему нужно, — каталог с правом
записи и открытый порт.

## Самый короткий путь

```sh
./kivorad
```

Слушает `:8080`, хранит данные в `./data`, отдаёт веб-клиент из себя же.
Зарегистрируйтесь первым — этот аккаунт становится администратором.

## Сборка

Нужны Go 1.24+ и Node 20+.

```powershell
.\build.ps1                  # Windows → dist\kivorad.exe
.\build.ps1 -Task release    # Windows → release\ под все платформы
```

```sh
./build.sh                    # Linux/macOS → dist/kivorad
./build.sh release            # → release/ для linux, windows, macos × amd64, arm64
make -f build.mk server       # то же самое через make
```

Кросс-компиляция не требует C-тулчейна: cgo нигде не используется.

**Сборка без доступа к реестру npm.** В закрытом контуре `npm install` не
пройдёт. Скрипты сборки это замечают и переключаются на bun:

```sh
node scripts/build-web.mjs   # то же самое вручную
```

Результат — тот же `web/dist`, который потом вкомпилируется в бинарник. Go-часть
собирается в закрытом контуре и так: в `go.mod` нет ни одной зависимости, а
`go.sum` пустой.

```sh
cd server
GOOS=linux   GOARCH=arm64 CGO_ENABLED=0 go build -trimpath -ldflags "-s -w" -o kivorad-pi   ./cmd/kivorad
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -ldflags "-s -w" -o kivorad.exe  ./cmd/kivorad
```

## Три поставки

`./build.sh package` (или `.\build.ps1 -Task package`) собирает три архива в
`dist/packages/`, потому что скачивают их три разных человека:

* **`kivora-server-<версия>`** — бинарники под amd64 и arm64, `install.sh`,
  конфиги Caddy/nginx/Docker, юнит systemd, автономная страница 404 и эта
  инструкция. Установка на сервер — одна команда `sudo ./install.sh`.
* **`kivora-windows-<версия>`** — `kivora.exe` и короткая инструкция: запуск
  двойным кликом, что делать со SmartScreen, как открыть порт в брандмауэре.
* **`kivora-linux-<версия>`** — бинарники x86-64 и ARM, автозапуск через
  пользовательский systemd.

Рядом кладётся `SHA256SUMS.txt` — самое дешёвое, что оператор может проверить,
и единственная защита самостоятельной раздачи от зеркала, которое врёт.

## Настройки

Всё задаётся переменными окружения, у всего есть рабочее значение по умолчанию.

### Сеть

| Переменная            | По умолчанию | Что делает                                                        |
| --------------------- | ------------ | ----------------------------------------------------------------- |
| `KIVORA_ADDR`          | `:8080`      | Адрес прослушивания                                               |
| `KIVORA_PUBLIC_URL`    | —            | Внешний адрес, если сервер за прокси                              |
| `KIVORA_TRUST_PROXY`   | `false`      | Верить `X-Forwarded-For`. **Включать только при реальном прокси**  |
| `KIVORA_CORS_ORIGINS`  | localhost+tauri | Источники, которым разрешён доступ к API                       |
| `KIVORA_SERVE_WEB`     | `true`       | Отдавать встроенный веб-клиент                                    |

### Хранилище

| Переменная                | По умолчанию | Что делает                                                     |
| ------------------------- | ------------ | -------------------------------------------------------------- |
| `KIVORA_DATA_DIR`          | `./data`     | Каталог данных (создаётся с правами 0700)                      |
| `KIVORA_SYNC`              | `always`     | `always` / `interval` / `never` — насколько упорно беречь данные |
| `KIVORA_SYNC_INTERVAL_MS`  | `200`        | Интервал для режима `interval`                                 |
| `KIVORA_COMPACT_PERCENT`   | `30`         | Доля удалённых сообщений, после которой журнал уплотняется при старте |

`always` — по умолчанию и правильный выбор для сервера с реальными людьми.
`interval` заметно быстрее и рискует потерять последние ~200 мс при отключении
питания. `never` — для одноразовых стендов.

### Безопасность

| Переменная                | По умолчанию | Что делает                                                    |
| ------------------------- | ------------ | ------------------------------------------------------------- |
| `KIVORA_REGISTRATION`      | `open`       | `open` / `invite` / `closed`                                  |
| `KIVORA_INVITE_CODES`      | —            | Коды через запятую для режима `invite`                        |
| `KIVORA_SESSION_TTL_HOURS` | `720`        | Срок жизни сессии (30 дней)                                   |
| `KIVORA_ARGON2_MEMORY_KIB` | `65536`      | Память Argon2id (64 МиБ)                                      |
| `KIVORA_ARGON2_TIME`       | `3`          | Проходы Argon2id                                              |
| `KIVORA_ARGON2_THREADS`    | `2`          | Параллелизм Argon2id                                          |
| `KIVORA_ALLOWED_SUITES`    | `*`          | Разрешённые наборы шифров                                     |
| `KIVORA_REQUIRE_E2E`       | `false`      | Запретить незашифрованные каналы                              |
| `KIVORA_MAX_DEVICES`       | `10`         | Устройств на аккаунт                                          |
| `KIVORA_RATE_RPS`          | `25`         | Запросов в секунду на IP                                      |
| `KIVORA_RATE_BURST`        | `60`         | Всплеск                                                       |
| `KIVORA_MAX_MESSAGE_BYTES` | `131072`     | Предел размера шифротекста сообщения                          |
| `KIVORA_MAX_UPLOAD_MB`     | `64`         | Предел размера тела запроса                                   |
| `KIVORA_MAX_FILE_MB`       | `32`         | Предел размера одного вложения                                |
| `KIVORA_MAX_AVATAR_KB`     | `2048`       | Предел размера аватара                                        |
| `KIVORA_RETENTION_DAYS`    | `0`          | Через сколько дней стирать сообщения. 0 — хранить вечно       |

`KIVORA_RETENTION_DAYS` — самая дешёвая мера приватности, которая у вас есть:
сообщение, которого больше нет, нельзя изъять, истребовать по запросу или
потерять при утечке. Никакая криптография этого не даёт. Срок применяется
вместе с таймером самого чата, и побеждает более ранний из двух; истечение
уничтожает завёрнутые ключи, а не прячет сообщение.

Слабый VPS: `KIVORA_ARGON2_MEMORY_KIB=32768`. Нормальное железо: `131072`.

Вложения занимают место в `blobs.dat` — том же файле, где лежат тела сообщений.
Считать надо по нему: `KIVORA_MAX_FILE_MB` × ожидаемое число файлов. Админ-панель
показывает текущий объём вложений и размер журнала.

### Звонки

| Переменная           | По умолчанию                   | Что делает                           |
| -------------------- | ------------------------------ | ------------------------------------ |
| `KIVORA_STUN_URLS`   | `stun:stun.l.google.com:19302` | STUN-серверы через запятую           |
| `KIVORA_TURN_URL`    | —                              | TURN-ретранслятор (`turn:host:3478`) |
| `KIVORA_TURN_USER`   | —                              | Логин TURN                           |
| `KIVORA_TURN_PASS`   | —                              | Пароль TURN                          |

Без TURN двое за симметричным NAT не соединятся — клиент честно показывает это,
потому что `GET /api/v1/ice` возвращает `hasRelay: false`. Для закрытого контура
поставьте свой coturn и уберите публичный STUN из списка: иначе адреса ваших
пользователей уходят наружу.

Медиа идёт напрямую между браузерами и через сервер не проходит — нагрузка на
сервер от звонка близка к нулю, а полосу тратят сами участники. Полносвязная
сеть означает, что каждый шлёт поток каждому: для звонка на 4–5 человек это
нормально, для конференции на 20 нужен SFU, которого здесь нет.


## systemd

Проще всего — через поставку для сервера:

```sh
tar xzf kivora-server-0.1.0.tar.gz
cd kivora-server-0.1.0
sudo ./install.sh
```

Скрипт заводит пользователя, ставит бинарник, создаёт каталог данных с правами
0700 и запускает службу; повторный запуск обновляет установку, не трогая
данные. Вручную то же самое:

`deploy/kivora.service`:

```sh
sudo useradd --system --home /var/lib/kivora --shell /usr/sbin/nologin kivora
sudo install -o kivora -g kivora -m 0755 dist/kivorad /usr/local/bin/kivorad
sudo install -d -o kivora -g kivora -m 0700 /var/lib/kivora
sudo cp deploy/kivora.service /etc/systemd/system/
sudo systemctl enable --now kivora
```

Юнит уже включает `ProtectSystem=strict`, `PrivateTmp`, `NoNewPrivileges`,
`MemoryDenyWriteExecute` и белый список системных вызовов — это дешёвая глубина
обороны, и сервер в ней прекрасно работает.

## TLS

Сервер намеренно не занимается сертификатами: этим лучше занимается тот, кто
делает это хорошо.

**Caddy** (`deploy/Caddyfile`) — сертификат получит сам:

```
chat.example.org {
	reverse_proxy 127.0.0.1:8080
}
```

**nginx** — готовый конфиг в `deploy/nginx.conf`; главное, не забыть про
`Upgrade`/`Connection` для WebSocket и `proxy_read_timeout` побольше, иначе
соединения будут рваться каждую минуту.

Если прокси отдаёт статику сам, отдайте ему и страницу ошибки:

```nginx
error_page 404 /404.html;
location = /404.html { root /var/www/kivora; internal; }
```

`web/public/404.html` — самостоятельная страница без единого внешнего файла
(ни скрипта, ни шрифта, ни картинки), поэтому работает, даже когда приложение
целиком недоступно. В поставке для сервера она лежит в `deploy/404.html`.

Сам сервер различает свои маршруты и мёртвые ссылки: `/` и `/admin/*` отдаются
с кодом **200**, всё остальное — с кодом **404** и телом веб-клиента, который
показывает ту же анимированную заглушку. Разница не косметическая: сплошной 200
прячет битые ссылки от любого монитора и краулера, а сплошной 404 объявляет
несуществующей настоящую админ-консоль.

Проверить это можно, не выдумывая битых ссылок: в админ-консоли есть раздел
«Страницы» с кнопками «открыть 404 внутри приложения», «открыть автономную
страницу» и «проверить код ответа».

При работе за прокси не забудьте:

```sh
KIVORA_TRUST_PROXY=true
KIVORA_CORS_ORIGINS=https://chat.example.org
```

## Docker

```sh
docker compose -f deploy/docker-compose.yml up -d
```

Образ собирается многостадийно и получается на базе `scratch`: внутри только
бинарник и корневые сертификаты, около 8 МБ.

## Клиенты

### Веб

Уже внутри бинарника, доступен по адресу сервера. Отдельная раздача:

```sh
KIVORA_SERVE_WEB=false ./kivorad
npm --prefix web run build   # → web/dist, положите куда угодно
```

Клиент подключается к серверу, с которого загружен; другой адрес указывается на
экране входа в разделе «Другой сервер».

### Десктоп

Нужен Rust 1.77+ и системные зависимости WebView.

**Windows 10/11:** Rust (MSVC), Visual Studio Build Tools, WebView2 (в Windows 11
уже есть; в Windows 10 доустановится сам). Затем:

```sh
npm --prefix desktop install
npm --prefix desktop run build     # → MSI и NSIS-установщик
```

**Linux (Debian/Ubuntu):**

```sh
sudo apt install libwebkit2gtk-4.1-dev libgtk-3-dev librsvg2-dev patchelf \
                 build-essential curl wget file libssl-dev
npm --prefix desktop install
npm --prefix desktop run build     # → .deb и .AppImage
```

Адрес сервера по умолчанию задаётся на экране входа и запоминается.

**Про звонки в Linux-сборке:** WebKitGTK не выдаёт разрешение на микрофон и
камеру из встроенного окна, поэтому звонки в десктоп-версии под Linux не
работают. Не потому, что не реализованы, — движок окна не пускает. В Windows
(WebView2) и в браузере на том же Linux всё работает. Обходной путь: открыть
веб-версию по адресу сервера. Как только WebKitGTK научится, поддержка включится
без изменений в коде клиента.

### Язык интерфейса

Язык определяется автоматически по `navigator.languages` и переключается в
настройках; выбор запоминается. Готовы русский и английский. Добавить третий —
это один файл `web/src/i18n/<код>.ts` типа `Record<Key, string>`: TypeScript сам
покажет незаполненные строки, потому что ключи выведены из русского словаря.

## Обновление

```sh
sudo systemctl stop kivora
sudo install -o kivora -g kivora -m 0755 dist/kivorad /usr/local/bin/kivorad
sudo systemctl start kivora
```

Формат журнала версионирован по записям; новые версии умеют читать старые файлы.
Резервная копия перед обновлением — всё равно хорошая привычка.

## Резервное копирование

```sh
systemctl stop kivora
tar czf kivora-$(date +%F).tar.gz -C /var/lib/kivora .
systemctl start kivora
```

Копия на живом сервере тоже почти всегда корректна (журнал только дозаписывается,
битый хвост отбрасывается при чтении), но остановка на секунду делает её
гарантированно целой.

`secret.key` из каталога данных **обязателен**: без него все сессии станут
недействительными.

## Диагностика

```sh
./kivorad -log debug
curl -s localhost:8080/api/v1/server | jq
```

**WebSocket не подключается за nginx** — нет заголовков `Upgrade`/`Connection`
или маленький `proxy_read_timeout`.

**«Сервер не принимает выбранный набор шифров»** — `KIVORA_ALLOWED_SUITES` не
содержит того, что умеет клиент. Проверьте `GET /api/v1/server`.

**Вход занимает секунды** — Argon2id настроен слишком дорого для этой машины,
уменьшите `KIVORA_ARGON2_MEMORY_KIB`.

**Звонок не соединяется** — почти всегда NAT. Проверьте `GET /api/v1/ice`: если
`hasRelay: false`, поставьте TURN. В Linux-десктопе звонков нет вовсе, см. выше.

**Файл не загружается** — либо больше `KIVORA_MAX_FILE_MB`, либо запрещённый
тип: `text/html`, `application/javascript`, `image/svg+xml` и
`application/xhtml+xml` отклоняются намеренно.

**Сообщения приходят как «не удалось расшифровать»** — обычно это сообщения,
отправленные до появления устройства. Откройте настройки на старом устройстве и
нажмите «Передать историю».
