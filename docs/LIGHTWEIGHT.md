# Вес приложения: что измерено и что ещё можно снять

Требование звучало как «обдумать варианты уменьшения веса». Ниже — что уже
сделано и сколько это дало, и что можно сделать дальше, с честной оценкой цены.
Все цифры получены на этой сборке, а не взяты из головы.

## Что получилось сейчас

| Артефакт                                      | Размер      |
| --------------------------------------------- | ----------- |
| `kivorad`, Linux amd64, вместе с веб-клиентом | **7,09 МБ** |
| он же, gzip (для скачивания)                  | 2,95 МБ     |
| `kivorad`, Windows amd64                      | 7,27 МБ     |
| `kivorad`, Linux arm64 (Raspberry Pi)         | 6,75 МБ     |
| Встроенный веб-клиент внутри бинарника        | **506 КБ**  |
| Веб-клиент по сети (gzip): JS + CSS           | **117 КБ**  |
| RSS сервера в работе                          | ~45 МБ      |

Это уже **с** эмодзи, звонками, ветками, аватарами, админ-панелью, страницей 404
и двумя языками. Прибавка ко всему прошлому набору функций — около 350 КБ в
бинарнике и 32 КБ по сети, и почти всё это данные, а не библиотеки: набор эмодзи
с поиском, два словаря локализации и брендовые картинки. Ни одной сторонней
зависимости не добавилось — ни в `go.mod`, ни в рантайме клиента.

Для сравнения: установленный Telegram Desktop — сотни мегабайт, типичное
Electron-приложение — 120–180 МБ на диске и 250–400 МБ памяти на вкладку.

## Решения, которые уже дали основной выигрыш

### 1. Tauri вместо Electron

Electron кладёт рядом с приложением собственный Chromium и Node. Tauri берёт
WebView, который в системе уже есть: WebView2 на Windows 10/11, WebKitGTK на
Linux. Экономия — примерно **100–150 МБ на установку** и большая часть памяти,
потому что второй браузер не запускается.

Цена честная: движки на платформах разные, поэтому что-то приходится проверять
дважды. Именно поэтому X25519 и Ed25519 имеют переносимый запасной путь на случай
WebView без нативной поддержки.

### 2. Ноль зависимостей на сервере

Ни одной строки в `go.mod`. Для сравнения: типичный набор из SQLite на чистом Go,
websocket-библиотеки и `x/crypto` добавляет 15–25 МБ к бинарнику. Здесь вместо
них — свои Argon2id, BLAKE2b, WebSocket и хранилище.

Это не только про размер: сборка работает без сети, кросс-компиляция не требует
C-тулчейна, а поверхность атаки на цепочку поставок равна нулю.

### 3. Клиент без библиотек

Никакого UI-фреймворка, никакого менеджера состояния, никакого пакета иконок.
Состояние — пятнадцать строк на `useSyncExternalStore`; иконки — три с половиной
десятка инлайновых SVG; крипта — свои примитивы. Из 116 КБ по сети на React с
React-DOM приходится большая часть, а весь код мессенджера — меньше половины.

Отдельно про то, чего обычно тянут пакетами:

* **Эмодзи** — `data/emoji.ts`: массив с русскими и английскими ключевыми
  словами. Типичная библиотека вроде `emoji-mart` весит 60–100 КБ плюс данные и
  ходит за спрайтами в сеть; здесь рисует шрифт системы.
* **Звонки** — голый `RTCPeerConnection` с «вежливым» разрешением коллизий.
  Обёртки вроде simple-peer добавляют 20–30 КБ и не делают ничего, чего нет в
  сорока строках.
* **Графики в админ-панели** — инлайновый SVG на десяток строк. Chart.js — это
  70 КБ gzip ради двух столбчатых диаграмм.
* **Локализация** — свой словарь с типизированными ключами и `{подстановкой}`.
  i18next весит больше, чем оба словаря вместе.

### 4. Флаги сборки

```toml
# desktop/src-tauri/Cargo.toml
[profile.release]
opt-level = "s"     # оптимизировать по размеру
lto = true          # межмодульная оптимизация
codegen-units = 1   # лучше оптимизация ценой времени сборки
panic = "abort"     # выбрасывает машинерию раскрутки стека
strip = true        # без таблиц символов
```

```sh
go build -trimpath -ldflags "-s -w"   # без отладочной информации и путей сборки
```

`-s -w` снимает с Go-бинарника около 30%.

## Что можно снять дальше

Отсортировано по отношению «выигрыш / цена». Ничего из этого не сделано — это
меню, а не список задач.

### Preact вместо React — минус ~35 КБ по сети

`preact/compat` — почти прозрачная замена. React с React-DOM это львиная доля
клиентского бандла; Preact весит около 4 КБ gzip.

Цена: несовместимости в редких углах React 19 и в devtools. Разумно, если целевая
аудитория сидит на медленных каналах.

### UPX для бинарника сервера — минус ~60% на диске

`upx --best --lzma dist/kivorad` обычно ужимает Go-бинарник до 2,5–3 МБ.

Цена настоящая: часть антивирусов реагирует на упакованные исполняемые файлы, и
старт становится чуть дольше. Для раздачи по сети лучше просто отдавать `.gz` —
почти тот же эффект без побочек.

### Ленивая загрузка админ-панели и звонков — минус ~20 КБ первой загрузки

Админ-панель нужна одному человеку из ста, `CallManager` — только когда звонят.
`React.lazy` вокруг обоих убирает их из первого чанка. Сделать это — полчаса; не
сделано, потому что на 116 КБ выигрыш пока не окупает лишнюю асинхронность.

### Выкинуть встроенный веб-клиент — минус 500 КБ

`KIVORA_SERVE_WEB=false`, а статику раздаёт nginx или Caddy. Экономия маленькая, но
если клиент уже лежит на CDN, дублировать его в бинарнике незачем.

### `GOGC` и `GOMEMLIMIT` — минус 30–50% RSS

Go по умолчанию щедр к памяти. На маленьком сервере:

```sh
GOGC=50 GOMEMLIMIT=192MiB ./kivorad
```

Цена: сборщик мусора работает чаще. Для нагрузки уровня команды это незаметно.

### Хранить историю сообщений на диске, а не индексом в памяти

Сейчас в памяти лежат метаданные всех сообщений (~150 байт на сообщение):
миллион сообщений — примерно 150 МБ. Для команды это неважно, для десятков тысяч
пользователей — уже да.

Вариант: держать в памяти только последние N сообщений на канал, остальное искать
по индексу на диске. Цена — усложнение самой аккуратной части кода; делать это
стоит по факту роста, а не заранее.

### Разделение бандла по маршрутам

Экран входа не нуждается в коде списка чатов. `React.lazy` вокруг основной
оболочки сократит первую загрузку примерно на треть. Vite уже вынесен в отдельный
чанк `crypto` — дальше это вопрос пары `lazy`.

### Своя мини-реализация вместо React

Клиент по сути — три списка и форма. На чистом DOM он уместится в 15–20 КБ.

Цена высока: любой, кто придёт править код, знает React и не знает вашего
фреймворка. Обычно это не окупается.

## Чего делать не стоит

* **Минифицировать имена ключей API.** Экономия — байты, а отладка становится
  мучением.
* **Сжимать WebSocket-кадры.** Сжатие рядом с секретами — это CRIME и BREACH; к
  тому же шифротекст не сжимается. Поэтому permessage-deflate в `internal/ws`
  отсутствует намеренно.
* **Убирать проверки ради размера.** Проверка подписи предключа — это байты кода
  и вся разница между «сервер не может читать» и «сервер может читать».
* **Хранить превью вложений на сервере в открытом виде.** Соблазн понятный:
  маленькая картинка вместо расшифровки. Но превью — это и есть содержимое
  фотографии, просто помельче. Поэтому заглушка считается на клиенте и едет
  внутри зашифрованного сообщения, а сервер получает только числа.
* **Ставить SFU ради «лёгких» конференций.** Это отдельный сервер, который видит
  медиапоток. Полносвязная сеть на 4–5 человек честнее и не требует ничего.

## Как измерить у себя

```sh
make -f build.mk release
ls -lh release/

# что именно занимает место в Go-бинарнике
go tool nm -size -sort size dist/kivorad | head -40

# что занимает место в клиенте
npm --prefix web run build   # Vite печатает размеры чанков и gzip
```
